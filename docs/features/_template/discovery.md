# Discovery

Use this document during discovery and requirements refinement. After approval, the current requirements and design become the implementation reading path. Preserve settled discovery as background, and carry unresolved questions into the active specification.

## Problem Statement

Describe the user or product problem without assuming a particular implementation.

## Desired Outcome

Describe what should become possible or meaningfully better.

## Users and Context

Identify affected users, their goals, and the context in which the feature is used. Link relevant project memory.

## Current Workflow

Describe how users handle the problem today, including workarounds and pain points.

## Current Product Behavior

Record verified behavior and relevant code locations. Label observations separately from owner-confirmed intent.

## Owner Vision

Record the owner's important expectations, examples, preferences, and non-negotiable qualities.

## Discovery Review Checklist

- [ ] The problem is described without locking in a solution.
- [ ] Affected users and workflows are understood.
- [ ] Current behavior has been checked against the code where relevant.
- [ ] Owner vision and non-negotiable qualities are recorded.
- [ ] Important assumptions are visible.
- [ ] Blocking questions are resolved or explicitly accepted for later resolution.
- [ ] The owner has approved the discovery gate in `README.md`.
